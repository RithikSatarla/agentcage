Demo

One refund, issued twice, and a suite that stays green.

An agent refunds a charge, loses the response, and retries. What your test says about that depends entirely on what it is talking to.

# one response, recorded from the real API, replayed forever
stripe = ReplayMock("responses.json")

charge = stripe.post_charge(amount=5000)
stripe.post_refund(charge=charge.id, amount=5000)
stripe.post_refund(charge=charge.id, amount=5000)
  1. refund 1200 succeeded
  2. refund 2200 succeeded
  3. your testpasses

The fixture has no memory, so the retry looks exactly like the original. The bug ships, and the customer is paid twice.

from part_b.stripe_mock import StripeMock

stripe = StripeMock()
charge = stripe.post_charge(amount=5000)

stripe.post_refund(charge=charge.id, amount=5000)
stripe.post_refund(charge=charge.id, amount=5000)
  1. refund 1200 succeeded
  2. refund 2400 charge_already_refunded
  3. your testfails

The model remembers the first refund, so the second is refused exactly as the real API would. You fix it before shipping.

Those four requests are a real recorded run, committed at traces/example_double_refund.json and asserted by the test suite. Reproduce the comparison with python -m part_b.demo_fixture_vs_model.

What just happened

  1. Intercept

    Your agent keeps its own HTTP client. AgentCage catches the request on its way out, without rewriting it.

  2. Model

    A stateful stand-in answers. It remembers the charge you already refunded and the file you already wrote.

  3. Assert

    The second refund is refused, the stale write is rejected, and your test fails where production would have.

All three showed bugs their own tests missed

Three open-source agent tools, their own code unchanged, pointed at a model that remembers what they already did.

camel-ai/camelGithubToolkit

Stale read

It reads a file from the default branch, then writes that version to a different branch. GitHub rejects the write. The tool never catches the error.

Its 9 tests pass with the entire GitHub library swapped for a mock that always says yes, so no version check ever runs.

agno-agi/agnoJiraTools

Duplicate write

One call to create an issue. Two issues created. The tool reports a single success.

run-llama/llama_indexJiraIssueToolSpec

Duplicate write

Written independently of agno, and wrong the same way. The retry happens inside the HTTP client, below the tool.

Three agents is a small number, and the models were built against these clients, so the clean parts of the result say more about fit than about generality. Every limitation is written down, alongside every request each agent made. Read the full result.
