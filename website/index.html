The bar was set as low as it goes. A tool counts as tested if its name appears anywhere in the project's test sources — no assertion required, no destructive path exercised, not even executed. One in five fails that. So 20.3% is a floor, not a ceiling.

Restricted to the 7 repositories whose entire test suite was read, the figure is 20.7%. The result doesn't depend on sampling.

What this does not say. The study detects framework-idiomatic tool definitions — @tool, BaseTool, JSON tool schemas. 32 of the 45 candidates screened out, including agents like aider and OpenHands that write to disk constantly but expose no such surface. The denominator of 13 reflects detector coverage as much as it reflects the ecosystem, and the protocol says so at length. Part A is exploratory, not pre-registered.

Why fixtures can't catch this

The standard way to test an agent is to record an HTTP response and replay it. A replay fixture holds no state, so it cannot express the failure mode specific to writes — an operation applied twice, or applied when it should have been refused.

refund(charge_id, 5000)   # fixture: 200 OK
refund(charge_id, 5000)   # fixture: 200 OK   <- suite passes
                          # Stripe:  400 charge_already_refunded
                          # reality: the customer was paid twice

The defect lives entirely in the state transition. No assertion over the fixture's responses can detect it. The suite isn't incomplete — it's structurally incapable.

The alternative

A model where writes mutate state and later reads observe the mutation.

from part_b.stripe_mock import StripeMock

stripe = StripeMock()
charge = stripe.post_charge(amount=5000, currency="usd")

stripe.post_refund(charge=charge.id, amount=5000)
stripe.get_charge(charge.id).amount_refunded   # 5000  <- the read sees the write

stripe.post_refund(charge=charge.id, amount=5000)
# StripeError: Charge ch_00000001 has already been refunded.
#              (400 charge_already_refunded)

Capture is passive — it attaches through each HTTP library's own hook points and never rewrites a request, injects a response, or short-circuits the transport. A test asserts that the caller receives exactly what the transport returned.

import httpx
from part_b.interceptor import Interceptor

cage = Interceptor()
client = httpx.Client(event_hooks=cage.httpx_event_hooks())

run_my_agent(client)

for trace in cage.writes:          # POST / PUT / PATCH / DELETE
    print(trace.method, trace.path, trace.status_code)

Reproduce it

git clone https://github.com/RithikSatarla/agentcage.git
cd agentcage
pip install -e ".[dev]"

pytest tests/            # 31 tests, no network
python -m part_a.run     # the full study, no credentials needed

The study makes 45 GitHub API calls, which fits inside the unauthenticated hourly limit. It re-runs weekly in CI, and every push re-runs the pipeline against the live API to prove it still works.
