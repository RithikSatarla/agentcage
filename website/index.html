We measured how much of this is tested

45 Python agent repositories screened. Every framework-idiomatic tool definition extracted mechanically, keeping the ones whose bodies perform a real state mutation.

The bar was set as low as it goes. A tool counts as tested if its identifier appears anywhere in the project's test sources — no assertion, no destructive path exercised, not even executed.

One in five fails that. So 20.3% is a floor, not a ceiling. Restricted to the 7 repositories whose entire suite was read, it is 20.7%.

Browse all 158 tools
What this does not say. 32 of the 45 candidates screened out. The study detects framework-idiomatic tool definitions — @tool, BaseTool, JSON schemas. Agents with bespoke architectures like aider and OpenHands write to disk constantly but expose no such surface. The denominator of 13 reflects detector coverage as much as the ecosystem.
Part A is exploratory, not pre-registered. The detectors were revised seven times, twice to remove false positives that would have made the finding look worse. All of them are in the paper.

Version-control and shell tools are the least tested

Running agents that write? Let’s talk.

The Stripe model is the first of many. Which API gets built next, and what fidelity it needs, should be decided by teams with a real agent in production rather than guessed.

What you get

  • A stateful model of the API your agent writes to, built to your failure cases
  • Direct input on the interceptor and test-harness design
  • Write paths exercised against real state transitions before they ship
  • MIT licensed — no lock-in, and it keeps working if we go away

What we need back

  • Which API, and which operations actually scare you
  • The failure modes you have already hit in production
  • Honest feedback on whether this catches anything real

No pricing, no contract, no waitlist. The code is public and the study is reproducible — start by running it and telling us where it is wrong.
