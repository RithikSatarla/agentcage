Reference

State, not recordings.

A model where writes mutate state and later reads observe the mutation. Deterministic identifiers, an injectable clock, and the real error codes — so a failure is a failure every time.

stripe_mock.py interceptor.py

Two halves

A passive capture layer, and a model to replay against.

part_b/interceptor.py passive

Attaches through each HTTP library's own documented hook points — httpx event hooks, requests response hooks. It records method, URL, path, query, headers, body and response status.

It never rewrites a request, injects a response, or short-circuits the transport. A test asserts the caller receives exactly what the transport returned, byte for byte.

Credential headers are replaced with <redacted> at capture time, which is what makes traces safe to commit.

part_b/stripe_mock.py stateful

An in-memory model of the money-moving subset of the Stripe API. Not a fixture: a refund increases charge.amount_refunded, and a later GET observes it.

Identifiers come from a counter (ch_00000001) and the clock is injectable, so a run is byte-for-byte reproducible.

Errors carry the real HTTP status, error code and message, returned in Stripe's error envelope.

Endpoints and rules

Every rule below is enforced by the model and asserted by the test suite.

EndpointBehaviourFailure
POST /v1/charges Creates a charge. capture=false leaves amount_captured at 0. parameter_invalid_integer for amount ≤ 0; 404 resource_missing for an unknown customer
GET /v1/charges/{id} Returns the charge with every mutation applied so far. 404 resource_missing
POST /v1/refunds Increases amount_refunded; sets refunded at parity. Amount defaults to the unrefunded remainder. 400 amount_too_large · 400 charge_already_refunded · 400 charge_not_captured
POST /v1/charges/{id}/refunds The nested route, same semantics. as above
GET /v1/refunds Lists refunds, filterable by charge. —
POST /v1/customers Creates a customer. —

The fidelity boundary

A mock's silent divergence from the real API is itself a source of false confidence, so the boundary is stated rather than discovered.

Not modelled: payment-method validation, 3-D Secure, disputes, payouts, balance transactions, webhooks, connected accounts, field expansion (expand[]), pagination cursors, rate limits, and Stripe's real identifier format. Refunding an uncaptured charge is rejected rather than releasing the authorisation as Stripe does.

The model is sufficient to exercise double-refund, over-refund, refund-after-refund and read-after-write. Nothing more is claimed.
